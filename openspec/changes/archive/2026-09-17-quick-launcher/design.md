## Context

现有项目是一个最小 Next.js 页面，首页只有 `StudyPower` 导航栏和空的主区域。需求是个人使用的快速启动器，当前没有账号、服务端数据或协作要求。

## Goals / Non-Goals

**Goals:**

- 在现有首页内完成可直接使用的快捷方式管理体验。
- 让搜索和打开动作不依赖服务端。
- 使用浏览器原生能力和现有依赖完成实现。
- 保持可访问的表单、按钮和链接语义。

**Non-Goals:**

- 不实现账号登录、云端同步、数据库或多人协作。
- 不实现拖拽排序、文件夹层级、图标上传或浏览器扩展。
- 不实现导图、Word 编辑和 AI 功能。

## Decisions

- 使用首页客户端组件管理搜索、表单和本地状态，因为这些交互只发生在浏览器端。
- 使用原生 `localStorage` 保存快捷方式，因为数据量小、范围是当前浏览器且无需额外依赖。
- 使用原生 `URL` 校验并限制为 HTTP/HTTPS 协议，避免把任意协议当作可启动链接。
- 使用原生 CSS 和字母图标，不引入图标库或 UI 组件库；当前功能不需要它们。
- 使用新标签页打开外部网址，并为外部链接设置 `noopener` 和 `noreferrer`。
- 首次使用提供少量通用默认入口，用户可以直接删除或新增自己的入口。

## Risks / Trade-offs

- [Risk] `localStorage` 只在当前浏览器保存，换设备不会同步 → [Mitigation] 当前定位为个人快速启动器；需要跨设备时再增加账号和云端存储。
- [Risk] 用户输入的网址可能失效或返回不可访问页面 → [Mitigation] 只校验协议和 URL 格式，不对第三方网站可用性做假设。
- [Risk] 新标签页可能被浏览器策略拦截 → [Mitigation] 点击和 Enter 都在用户手势事件中直接调用 `window.open`。

## Migration Plan

1. 在现有首页增加快速启动器客户端交互和样式。
2. 保留现有导航栏和页面启动命令。
3. 执行生产构建和浏览器交互验证。

回滚时恢复首页组件和全局样式到变更前版本；由于配置只写入浏览器本地存储，不涉及服务端迁移。
