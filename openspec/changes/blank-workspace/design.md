## Context

本地目录和远程 GitHub 仓库均为空，项目没有既有技术约束。需求只包含一个导航栏和空白正文，因此设计以最少运行部件为目标，不提前加入编辑器、导图、数据库、认证或实时协作。

## Goals / Non-Goals

**Goals:**

- 创建一个可独立运行的 Web 项目。
- 使用单一应用承载页面和后续扩展空间。
- 让导航栏有明确的视觉边界，正文不产生额外视觉内容。
- 通过本地构建和生产启动检查验证交付结果。

**Non-Goals:**

- 不实现思维导图。
- 不实现 Word 或富文本编辑。
- 不实现数据库、账号、同步、附件、搜索或 AI。
- 不引入微服务或额外部署服务。

## Decisions

- 使用 Next.js、React 和 TypeScript：将页面、开发服务和生产构建放在一个项目中，适合当前空仓库和后续工作台扩展。
- 使用原生 CSS 完成导航栏：当前只有简单布局，不为视觉基础引入组件库或设计系统。
- 首页只保留导航栏：导航栏显示 `StudyPower`，其余页面区域使用空的主容器承载，避免自行添加未确认的业务内容。
- 采用最小依赖集合：只安装运行页面所必需的依赖，后续功能按实际需求增加。

## Risks / Trade-offs

- [Risk] 当前导航栏没有具体业务入口，后续需要重新定义导航内容 → [Mitigation] 保留清晰的导航容器和品牌名称，下一阶段按确认后的信息架构补充入口。
- [Risk] 使用最小页面骨架无法提前验证导图和文档编辑性能 → [Mitigation] 当前需求不包含这些功能，待功能需求确认后再针对真实交互做验证。

## Migration Plan

1. 在空的本地根目录创建项目文件。
2. 执行依赖安装、生产构建和生产启动检查。
3. 提交初始代码并推送到指定远程仓库。

如构建或启动检查失败，先修复本地代码并重新验证；推送前不保留未经验证的版本。
